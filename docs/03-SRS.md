# 03 -- SRS (Software Requirements Document)

## 1. Functional
- FR1: `jevClient.ts` -- `POST https://openrouter.ai/api/alpha/decisions`, `{model, state, questions}`, Zod-validate `answers + usage`. Timeout 15s, no auto-retry on unknown outcome (may already be billed).
- FR2: `taxonomy.ts` -- fixed axes, **dynamic criteria**. Axes: `domain, compute, data, backend, frontend, infra, auth, repo_layout`. Criteria values generated by Ollama per brief, 3-5 options each with description.
- FR3: `candidateProposer` (Ollama) -- output JSON `{axis, ranked:[{id, why, scalability, security, cost, whenNot}]}` best->least.
- FR4: `policy.ts` -- thresholds above; low-confidence escalation to REPL.
- FR5: `ollamaClient.ts` -- `http://localhost:11434/api/chat`, single `OLLAMA_MODEL`, temp 0.2 for docs, 0.7 for chat.
- FR6: `pipeline.ts` -- ordered generation, context chaining, `TODO` on missing decision.
- FR7: `files.ts` -- workdir-sandboxed `mkdir/write/edit`, deny `..` escape, diff preview.
- FR8: `guard.ts` -- Jev noul triage + refusal + audit log.

## 2. Data
- `projectState.json`: `{brief, domain, constraints, answers, jevDecisions}`
- `decisions.log.json`: append-only `{ts, model, questionIds, answers, confidence, usage.cost}`
- Env: `OPENROUTER_API_KEY, JEV_MODEL=typesafe/jev-1.13, OLLAMA_HOST, OLLAMA_MODEL`

## 3. Interfaces
- Jev Decisions API (OpenRouter): `model/state/questions -> answers/usage`. Bare `jev-1.13` also works via `POST /api/v1/systemone`.
- Ollama Chat API locally. `ollama list` for `/model` picker.
